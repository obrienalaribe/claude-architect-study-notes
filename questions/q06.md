# Question 6

Original practice question. Not from any exam.

## Scenario

A payments startup runs Claude Code as a reviewer on every push to an open pull request. One pull request received six pushes, and the same four comments were posted after each push. Engineers have started ignoring the reviewer.

## Question

What should change in the review job?

- **A.** Run the review only on the first push of each pull request.
- **B.** After each run, delete any new comment whose text exactly matches a comment posted on an earlier push.
- **C.** Add "do not repeat yourself" to the review criteria in CLAUDE.md.
- **D.** Pass the earlier findings into each run and ask for only new or still-unresolved issues.

<details>
<summary>Answer and reasoning</summary>

**Answer: D.** Each CI run starts without knowledge of what earlier runs reported. Supplying the prior findings and asking only for new or unaddressed issues removes the duplicates and keeps later commits covered.

Why the others fail:

- **A.** Problems introduced by later commits would never be reviewed.
- **B.** It patches the symptom after the fact and depends on identical wording, while the run still lacks the earlier findings.
- **C.** A fresh run has no record of what it said before, so there is nothing for it to avoid repeating.

Exam domain: 3, Claude Code Configuration and Workflows. Task statement: 3.6.
