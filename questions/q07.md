# Question 7

Original practice question. Not from any exam.

## Scenario

A recruitment platform extracts candidate details from CVs through a tool with a JSON schema. `notice_period_days` is a required integer, yet only about a third of CVs state a notice period. Spot checks show the field is always filled, usually with 30.

## Question

Which change best stops the invented values?

- **A.** Make the field optional and nullable so the model can return null when the CV does not say.
- **B.** Keep the field required and add "never guess" to the extraction prompt.
- **C.** Validate each result and retry with specific error feedback whenever the returned value is exactly 30.
- **D.** Set `tool_choice` to "any" so the model must always call an extraction tool.

<details>
<summary>Answer and reasoning</summary>

**Answer: A.** A required field forces a value even when the source has none, which pushes the model to make one up. Marking it nullable gives the model an honest way to say the information is absent. Today: native structured outputs (output_config.format, strict: true) guarantee the schema, but checking the meaning is still your job.

Why the others fail:

- **B.** The schema still demands an integer, so the instruction and the schema pull in opposite directions.
- **C.** A retry cannot recover information that is not in the document.
- **D.** That guarantees a tool call, not a truthful value.

Exam domain: 4, Prompt Engineering and Structured Output. Task statement: 4.3.
