# Question 4

Original practice question. Not from any exam.

## Scenario

A nine-person analytics team wants every engineer's Claude Code to reach the same data warehouse schema server. One engineer has it working from her personal configuration with an access token pasted in. New joiners keep asking how to set it up.

## Question

What is the best way to roll this out?

- **A.** Have each engineer copy her entry into their own `~/.claude.json`, token included.
- **B.** Commit a project `.mcp.json` that defines the server and reads the token from an environment variable such as `${WAREHOUSE_TOKEN}`.
- **C.** Commit a project `.mcp.json` with the token written inline so the server works straight after cloning.
- **D.** Describe the server, its launch command and its setup steps in the project CLAUDE.md so that Claude connects to it at the start of each session.

<details>
<summary>Answer and reasoning</summary>

**Answer: B.** Shared team tooling belongs in the project-scoped `.mcp.json`, and environment variable expansion keeps the credential out of version control. Everyone gets the server on clone and supplies their own token locally.

Why the others fail:

- **A.** User-level configuration is for personal or experimental servers; it is not shared, so every new joiner repeats the setup.
- **C.** It shares the server but commits a secret to the repository.
- **D.** CLAUDE.md carries instructions and context. Shared server configuration lives in `.mcp.json`.

Exam domain: 2, Tool Design and MCP Integration. Task statement: 2.4.
