# Question 1

Original practice question. Not from any exam.

## Scenario

A freight forwarder runs a rebooking agent on the Claude API. Its loop stops as soon as a response contains any assistant text. In about 1 of every 7 runs the agent writes "Checking carrier schedules now" in the same response as a tool request, and the run ends before the tool executes.

## Question

Which loop control fixes this most reliably?

- **A.** Cap the loop at 12 iterations and treat reaching the cap as completion.
- **B.** End the loop when the reply contains a completion phrase such as "rebooking complete".
- **C.** Keep looping while `stop_reason` is "tool_use", run the requested tools, and stop on "end_turn".
- **D.** Instruct the model in the system prompt never to write text alongside a tool request.

<details>
<summary>Answer and reasoning</summary>

**Answer: C.** The stop reason is the structural signal for the loop: continue on "tool_use", return the tool results, and finish on "end_turn". Text in a response says nothing reliable about whether the work is done. Today: the API has more stop reasons (pause_turn, refusal, max_tokens and others), but the rule is the same: continue on tool_use and never invent an exit.

Why the others fail:

- **A.** An arbitrary iteration cap as the primary stopping mechanism is a named anti-pattern; it can end a run before the work is done.
- **B.** Parsing natural language for a completion phrase is fragile; the model may word it differently or say it early.
- **D.** The loop would still key off text, which is the wrong signal, and a prompt rule will not hold every time.

Exam domain: 1, Agentic Architecture and Orchestration. Task statement: 1.1.
