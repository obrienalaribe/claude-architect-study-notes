# Question 3

Original practice question. Not from any exam.

## Scenario

A property manager exposes an MCP tool, `find_lease_records`, to a tenant help agent. The tool returns an empty list when no lease matches and also when the records database times out. Last month 41 tenants were wrongly told they had no lease on file.

## Question

Which change to the tool best lets the agent respond correctly?

- **A.** Return the text "Operation failed" for both cases so the agent stops telling tenants anything definite.
- **B.** Raise the tool's database timeout from 5 to 60 seconds and keep returning an empty list when a lookup still fails after the longer wait.
- **C.** Add a system prompt rule telling the agent to call the tool again whenever a result comes back empty.
- **D.** On a timeout, set `isError` and return a transient category with a retryable flag; keep the empty list for true no-match results.

<details>
<summary>Answer and reasoning</summary>

**Answer: D.** An access failure and a successful query with no matches need different handling, so the tool has to report them differently. Structured error metadata tells the agent the failure is transient and worth retrying, while a real empty result can be stated with confidence.

Why the others fail:

- **A.** One generic message for every case removes the information the agent needs to choose a recovery step.
- **B.** A longer wait still reports a failure as an empty success, which is the original bug.
- **C.** The agent still cannot tell the two cases apart, and it wastes calls on every valid empty result.

Exam domain: 2, Tool Design and MCP Integration. Task statement: 2.2.
