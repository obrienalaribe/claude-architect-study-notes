# Question 5

Domain 3, Claude Code Configuration and Workflows. Task statement 3.2.

## Scenario

A platform team shares a skill, `dep-audit`, that walks the dependency tree and prints about 3,000 lines of findings. Engineers run it in the middle of feature work. Afterwards Claude loses track of the feature it was building.

## Question

Which change addresses the cause?

- **A.** Move the audit instructions into the project CLAUDE.md so they load with every session and need no skill.
- **B.** Add `context: fork` to the skill's frontmatter so it runs in an isolated sub-agent context.
- **C.** Set `allowed-tools` in the frontmatter so the skill is limited to read-only tools and cannot edit files.
- **D.** Move the skill to `~/.claude/skills/` so each engineer runs a personal copy.

<details>
<summary>Answer and reasoning</summary>

**Answer: B.** The verbose output is flooding the main conversation. Forking the skill's context runs it in isolation, so the bulk of the output stays out of the session doing the feature work.

Why the others fail:

- **A.** CLAUDE.md is for always-loaded standards; a task-specific workflow there adds context to every session and isolates nothing.
- **C.** That limits what the skill can do, not where its output lands.
- **D.** That changes who has the skill, not where it runs.

</details>
